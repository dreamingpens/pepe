We are going to create a paper-reader application. 

1. It should be SUPER simple in terms of ui/ux. The UI should not distract the paper reading at all. So unless we unfold the tab (like a side menu for ai chat), there should be absolutely no buttons, menus, or any other UI elements visible on the screen except for main tab for paper. The focus should be solely on the paper content.
2. The second important one is the speed. If needed, the backend should be implemented in rust if it is faster than js.  
3. If we press command + l, the ai chat tab should unfold from the right side of the screen, allowing users to interact with the AI chat without leaving the paper reading experience. The AI chat should be context-aware, meaning it can provide insights, summaries, or answer questions related to the content of the paper being read. If we press command + l while the selected text is highlighted, the AI chat should automatically take that highlighted text as context for the conversation. Of course, if we press command + l again, the AI chat tab should fold back to the right side of the screen, hiding it from view. It should support codex subscription oauth, should support the frontier model of astro model. We should also support fast mode, verbosity, thinking level. The ui example of ai chat is saved in images/ai-chat folder. Also the ai should provide the reference of the answer from the paper, and if the user clicks the reference line, the application should automatically scroll to the corresponding section in the paper. The AI chat should also support multi-turn conversations, allowing users to ask follow-up questions or request further clarification on specific points. Also we can search the chat history and re-start the conversation from one of those.
4. Next feature should be downloading and loading citation paper. If we click the citation representation in the paper (e.g. [1], [2], [author, year], [et al..], etc; There are various formats for citation, so download arbitrary numerous ai papers from arxiv and test them), the mini window pops out near the citation, which provides download button and summarize button. The download button allows users to download the cited paper directly, while the summarize button provides a brief summary of the cited paper's content. This feature should also support citation management, allowing users to keep track of their references and easily access them later. This application should have the extra paper management feature, which shows the list of papers which are saved in certain local directory and easily open one of the papers in the list. So there should be also open button in the mini window for the cited paper, which just open the cited paper without downloading it. Thus there should be also the download feature for any opened paper.
5. The initial page of the application should be a simple dashboard that allows users to open a paper from their local directory or download a paper from an online source. The dashboard should also provide access to the user's saved papers and citation management features. The user should be able to search for papers by title, author, or keywords, and the search results should be displayed in a clean and organized manner. We should be also able to make and manage some subdirectories in the local root paper directory, while the citation subdirectory should be automatically created and managed by the application. The citation subdirectory should store all downloaded papers by the citation download.
6. After downloading the paper, the application should automatically summarize the paper simply by bullet points format. This process should be lazy loaded, meaning that it should not block the user from reading the paper or application to download it fully. If the focus is on the certain paper in the dashboard, the application should also provide a quick summary of the paper in the dashboard itself, allowing users to quickly assess the relevance of the paper before opening it. The summary should be generated using AI and should highlight the key points and findings of the paper. The user should also have the option to customize the summary format, such as choosing between bullet points or a paragraph format.
7. The formula and figures should be parsed wholely, so that the ai chat can provide explanations for them easily. Also when clicking on the figure or formula, the application should provide an mini window for explanation of it by ai.
